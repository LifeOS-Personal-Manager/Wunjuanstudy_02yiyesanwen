# 散文贴图生产台产品文档

> 文档版本：MVP 1.0  
> 更新日期：2026-09-02  
> 正式地址：[https://essay-image-studio.pages.dev](https://essay-image-studio.pages.dev)

## 1. 产品定位

散文贴图生产台是一套面向微信公众号等内容发布场景的内部生产工具。用户输入散文篇名和作者，系统自动检索公开来源；在没有可用公开来源时，可由服务端 DeepSeek 生成明确标记的“AI 补全文”候选。用户确认正文版本后，系统据此生成 6 张竖版图卡的内容结构、提示词、草图、排版和发布包。

产品解决的是“文字策划、图片匹配、固定排版、发布资料整理”之间反复切换的问题，不替代版权核验与外部生图平台。

## 2. 目标用户与使用前提

### 目标用户

- 公众号、小红书等图文内容编辑。
- 文学内容运营人员。
- 需要将散文拆解为连续视觉图文的创作者。

### 使用前提

- 使用者已通过 Cloudflare Access 登录受保护站点。
- 生产环境已配置 D1、R2 和服务端 DeepSeek 密钥。
- 使用者对待发布的文本版本、授权范围和图片版权负责。

## 3. 核心价值

1. 仅输入篇名和作者即可开始索引，减少手工录入。
2. 将一篇散文固定拆为“封面 + 4 张正文 + 结尾”6 张图卡，适合连续发布。
3. 所有原文短摘必须逐字来自已确认的完整正文，避免 AI 改写原文后混入成品。
4. 生图提示词、图像、裁剪、文字位置与导出资料在同一工作台管理。
5. 采用固定 1080 x 1440 画布，预览和导出保持同一坐标体系。

## 4. 完整业务流程

```text
输入篇名 + 作者
        |
        v
公开来源检索 -> 全网公开页面检索 -> DeepSeek 补全文候选
        |
        v
用户核对版本、版权与正文后确认
        |
        v
DeepSeek 生成 6 张图卡结构（严格 JSON）
        |
        v
服务端逐字校验短摘来自完整原文
        |
        v
编辑图卡 / 管理提示词 / 生成草图或上传正式图片
        |
        v
裁剪与调整文字位置 -> 预览
        |
        v
单张导出或导出 ZIP 发布包
```

## 5. 功能说明

| 模块 | 已实现能力 | 产出 |
| --- | --- | --- |
| 新建散文 | 输入篇名、作者；自动索引并填充候选全文；确认来源与版权说明 | 已保存的散文项目 |
| AI 分析 | DeepSeek 生成 1 封面、4 正文、1 结尾的图卡提案 | 6 张图卡与发布文案 |
| 图卡管理 | 编辑短摘、导读、场景描述、提示词；排序、删除、单卡重新生成 | 可编辑图卡结构 |
| 提示词 | 展示全部提示词；单条复制、全部复制、下载 Markdown | `提示词.md` |
| 图片管理 | 批量上传、单张替换；为缺图卡生成无文字草图 | R2 图片资产与图卡关联 |
| 自动排版 | 封面、正文、结尾三类模板；裁剪、缩放、文字位置调整 | 1080 x 1440 预览 |
| 导出 | PNG/JPG 单张导出；全部图卡、提示词、发布文案、清单 ZIP 导出 | 发布包 |

### 5.1 原文与 AI 的边界

- `sourceExcerpt` 必须通过 `originalText.slice(start, end) === sourceExcerpt` 校验。
- DeepSeek 只负责提出短摘位置、导读、场景和提示词；不得作为最终原文来源。
- 当 AI 返回的短摘无法逐字命中正文时，系统保留 AI 的策划信息，并从确认正文中按段落位置截取回退短摘。
- AI 补全文候选会显示为“AI 补全文”，不等同于权威版本或转载授权。

### 5.2 成品图片中包含什么

最终排版画布只包含：散文标题（仅封面）、原文短摘、作者、页码和“一页散文”标识。

编辑导读与生图提示词仅在工作台的图卡编辑页、提示词页显示，不会进入排版预览、单张导出或 ZIP 图片。

## 7. 输出规范

### 图片

- 固定尺寸：`1080 x 1440`。
- 可选格式：PNG 或 JPG。
- 图卡顺序：`01-cover`、`02-body`、`03-body`、`04-body`、`05-body`、`06-ending`。

### ZIP 发布包

```text
{散文名}/
├─ images/
│  ├─ 01-cover.png
│  ├─ 02-body.png
│  ├─ 03-body.png
│  ├─ 04-body.png
│  ├─ 05-body.png
│  └─ 06-ending.png
├─ prompts.md
├─ publication-copy.md
└─ manifest.json
```

## 8. 技术与部署架构

```text
React + Vite + TypeScript
          |
          v
Cloudflare Pages（静态站点）
          |
          v
Pages Functions /api/*
    |           |           |
    v           v           v
Cloudflare D1  Cloudflare R2  DeepSeek API
```

| 层级 | 技术与职责 |
| --- | --- |
| 前端 | React、Vite、TypeScript、Tailwind CSS、shadcn/ui 风格组件 |
| 服务端 | Cloudflare Pages Functions，提供鉴权、D1/R2 访问和 DeepSeek 调用 |
| 数据库 | Cloudflare D1，保存散文、图卡、分析记录、图片元数据与用量记录 |
| 文件存储 | Cloudflare R2，保存上传原图、草图和渲染后的图片 |
| AI | DeepSeek API，仅由服务端调用 |
| 本地渲染 | HTML/CSS + `html-to-image` 生成图片，JSZip 打包下载 |

## 9. 安全、版权与数据策略

1. `DEEPSEEK_API_KEY` 只存于 Cloudflare Pages Secret，浏览器、源代码和 API 响应均不得获取该密钥。
2. 站点通过 Cloudflare Access 保护，未登录请求不能访问业务 API 与 R2 内容代理。
3. D1 是业务数据事实来源；R2 仅保存二进制资产，前端通过同域 API 读取，不直接公开 bucket。
4. 图片上传限制为 JPEG、PNG、WebP，单张最大 10 MiB，并校验文件签名、尺寸和像素数。
5. 任何“AI 补全文”及公开网页文本都必须在发布、转载或商用前与授权版本逐字核验。
6. 当前版本使用 Cloudflare Access 做内部访问控制；如面向多人或公众使用，需要增加独立账号、项目级授权与审计策略。

## 10. 限流与异常说明

- 文章检索：每位用户每小时最多 60 次。
- DeepSeek 整篇分析与单卡重新生成：每位用户每小时最多 80 次。
- 达到 DeepSeek 六卡生成额度时，页面会明确提示“全文已索引，但六卡生成暂受限”，候选全文不会丢失。
- DeepSeek 上游错误、超时或 JSON 不合格时，不写入半成品图卡，原有有效图卡保持不变。

## 11. 当前 MVP 边界与后续建议

- 目前不直接调用第三方生图平台，正式图片仍需在外部平台生成后上传。
- 图片渲染和 ZIP 打包在浏览器完成；受浏览器下载策略影响时，可优先使用“导出当前图卡”验证单图结果。
- 当前无多人实时协作，仅通过版本号避免覆盖编辑。
- 建议将本机项目推送到私有 GitHub 或 Gitee 仓库，并按 [正式上线与运维手册](production-runbook.md) 定期备份 D1、R2 与部署配置。
