# 散文贴图生产台开发日志

> 项目：散文贴图生产台 MVP  
> 记录截至：2026-09-02  
> 生产地址：[https://essay-image-studio.pages.dev](https://essay-image-studio.pages.dev)

## 1. 项目目标

构建一套将散文转换为 6 张微信竖版贴图的生产工具。核心要求是：用户输入篇名和作者即可自动索引全文；DeepSeek 生成图卡策划信息；原文短摘必须从确认正文逐字截取；用户可完成图片、排版和发布包导出。

## 3. 主要实现记录

### 3.1 架构与数据建模

- 前端采用 React、Vite、TypeScript；路由覆盖项目、图卡、提示词、图片、排版和导出。
- 后端采用 Cloudflare Pages Functions，所有 `/api/*` 请求同域处理。
- D1 建立 `essays`、`cards`、`assets`、`analysis_runs`、`export_jobs` 等业务表。
- R2 存储原始图片、草图与渲染结果；D1 只保存资产元数据和关联关系。
- DeepSeek 密钥使用 Cloudflare Pages Secret，不写入浏览器、源码或日志。

### 3.2 自动索引与全文补全

初版要求用户粘贴完整原文。后续调整为“输入篇名 + 作者”自动完成：

1. 优先通过中文维基文库直接页面与搜索接口检索。
2. 若没有结果，尝试通过 Brave Search 搜索全网公开页面并抽取段落。
3. 若仍无候选，服务端调用 DeepSeek 生成标注为“AI 补全文”的候选。
4. 返回候选的来源、正文长度、版权说明与来源链接，供用户确认。
5. 用户确认后创建 D1 项目并调用 DeepSeek 生成 6 张图卡。

已用《背影》《荷塘月色》《藤野先生》《济南的冬天》《从百草园到三味书屋》等文章实际验证索引与六卡生成流程。

### 3.3 原文短摘可靠性修复

问题：DeepSeek 有时会对原文短摘进行轻微改写、使用异体字或省略标点，导致无法精确命中用户确认的完整正文。

处理：

- 服务端不再接受未经校验的 AI 原文。
- 对每张卡执行逐字匹配，并以 AI 位置提示选择匹配位置。
- 当 AI 短摘不匹配时，保留其导读、场景和提示词，改从当前原文的对应段落截取短摘。
- 最终写入卡片的 `sourceExcerpt` 始终可由 `originalText.slice(sourceStart, sourceEnd)` 复原。

结果：避免因为单个 AI 引文不精确造成整批图卡无法生成，同时不允许 AI 编造原文进入发布成品。

### 3.4 项目路由与底图显示修复

问题一：直接打开 `/essays/:id/layout` 时，Store 没有及时切换当前项目，偶尔显示前一个项目或《蝌蚪》示例。

处理：Shell 读取 URL 中的 `essayId`，在服务端工作区加载后调用 `openProject` 切换当前项目。

问题二：新项目无底图时会回退到《蝌蚪》的演示图片，造成内容错配。

处理：改为中性“待上传底图”画布；资产页与排版缩略图统一显示空状态，不再使用示例图作回退。

### 3.5 免费草图工作流

需求：在尚未使用外部生图平台前，先有可用于验证排版的草图。

实现：

- 新增 `src/lib/draftSketch.ts`，通过浏览器 Canvas 按标题、作者、场景和图卡序号确定性绘制无文字水墨风草图。
- 图片页增加“生成草图”。
- 只对未关联底图的图卡生成草图，已上传正式图不被覆盖。
- 云端项目将草图上传 R2 并写回 `sourceAssetId`；本地模式使用 data URL。

### 3.6 上传 API 契约修复

问题：前端 `uploadAsset()` 预期接口返回 `{ asset }`，服务端曾返回裸资产对象，导致上传成功后前端无法正确关联图卡。

处理：统一为 `{ asset: mapAsset(asset) }` 响应结构。上传后的图片能够自动匹配并在资产页、排版页显示。

### 3.7 导出兼容性与单张导出

问题：导出阶段曾使用 `fetch(dataUrl)` 将 `html-to-image` 的 data URL 转 Blob，部分浏览器环境会抛出 `TypeError: Failed to fetch`，导致 ZIP 中断。

处理：

- 改为 `atob` + `Uint8Array` 直接将 data URL 转为 Blob。
- 新增图卡下拉选择与“导出当前图卡”，支持按 PNG/JPG 单张下载。
- 将渲染副本上传 R2 改为 best effort，不阻断浏览器本地下载。
- 导出前将受 Access 保护的图片内嵌为 data URL，降低 `html-to-image` 二次请求 R2 时的失败风险。

### 3.8 排版图片混入提示词 / 导读修复

问题：用户发现排版预览与导出图片中混入不应出现的长段文字。排查确认其来源是 `editorGuide`，不是 `imagePrompt`。

处理：从 `CardCanvas` 最终画布移除编辑导读层，并删除对应样式。提示词和编辑导读保留在工作台数据与编辑界面，但不参与预览、单张导出、ZIP 图片渲染。

结果：最终图片仅保留标题、原文短摘、作者、页码和标识。

### 3.9 DeepSeek 限流修复

问题：新建页在“全文索引成功”后自动创建项目并分析六卡。系统早期把整篇分析限制为每用户 `30 次/24 小时`，测试和正常使用叠加后会显示“请求过于频繁”，同时页面仍展示成功候选，造成状态矛盾。

处理：

- 调整为 DeepSeek 整篇分析与单卡重新生成每用户 `80 次/小时` 的滑动窗口额度。
- 限流异常携带操作类型、额度和窗口信息。
- 对六卡分析限流显示“全文已索引，但六卡生成在当前小时达到安全额度；候选全文不会丢失”。

结果：避免测试调用占用整日额度，并让用户能区分“索引成功”和“生成暂受限”。

## 6. 当前风险与后续工作

1. AI 补全文和网页抓取结果可能与权威版本存在文字差异，发布前仍必须由编辑逐字核验版权与版本。
2. 浏览器端图片导出会受到浏览器下载策略、内存和 Access 保护资源的影响。发布前应至少先用单张导出检查成图。
3. 当前为内部单租户 MVP。若开放给多人，需要完善账号体系、项目级权限、用量计费、审计和内容留存策略。
4. 源码当前主要保存在本机项目目录。建议建立私有 GitHub/Gitee 仓库，并定期备份 D1、R2 与 Cloudflare 配置。
5. 如导出规模扩大或需要服务端异步任务，可将长耗时任务迁移到 Cloudflare Workers + Queues。
